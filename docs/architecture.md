# Architecture

`pc-control` combines four Antigravity plugin primitives into one cohesive Windows automation bundle:

```text
Antigravity Agent
  ├── rules/AGENTS.md              (Always-on Tier 1/2/3 safety guardrails)
  ├── skills/*/SKILL.md + *.ps1    (Playbooks for GUI, diagnostics, network/power, maintenance)
  └── mcp_config.json              (Spawns local stdio MCP server via uv)
        └── server/pc_control_mcp.py
              ├── _ScreenWatcher   (Background 1280px JPEG frame buffer)
              ├── Win32 / psutil   (Windows, processes, services, files)
              ├── pyautogui        (Batched DPI-aware mouse & keyboard)
              └── _GuardClient ──► server/overlay_guard.py
                                     ├── 4x UpdateLayeredWindow border strips
                                     ├── 1x Top-center interrupt warning pill
                                     └── WH_KEYBOARD_LL + WH_MOUSE_LL hooks
```

## 1. DPI Awareness & Coordinate Spaces

On Windows displays with 125%–200% scaling, mixing logical coordinates with physical screenshot pixels causes off-target clicks. Both `pc_control_mcp.py` and `overlay_guard.py` call `SetProcessDpiAwareness(2)` (Per-Monitor DPI Aware) before initializing `mss`, `pyautogui`, or Win32 windows.

`take_screenshot` stores the captured monitor/window region and downscaled image dimensions in `_LAST_CAPTURE`, enabling three coordinate modes:
- `screen`: Raw physical desktop pixels.
- `last_screenshot`: Coordinates read directly from the most recent screenshot (automatically mapped back to physical screen pixels).
- `normalized_1000`: Resolution-independent `0..1000` coordinates.

## 2. Background Screen-Watcher (`_ScreenWatcher`)

When `take_screenshot` or `control_session(action="start")` is invoked, `_ScreenWatcher` starts a daemon thread that captures the primary monitor every `~0.35s` and stores a `1280px`-wide `JPEG` (`quality=78`) in memory. If no capture request occurs for `30s`, the thread exits automatically so idle CPU usage stays at zero.

## 3. Overlay Ring & Physical Input Lock (`overlay_guard.py`)

Win32 low-level hooks (`WH_KEYBOARD_LL`, `WH_MOUSE_LL`) require an uninterrupted `GetMessageW` pump and a fast window update loop. Running `overlay_guard.py` in a dedicated child process isolates the message pump from MCP tool I/O:

- **Click-Through Layered Borders**: Four `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` strip windows render a rotating gradient border using `UpdateLayeredWindow` without ever stealing window focus.
- **Injected vs. Physical Input Filtering**: Hooks inspect `LLKHF_INJECTED` (keyboard) and `LLMHF_INJECTED` (mouse). Automation events generated by `pyautogui` / `SendInput` pass through, while physical human events are swallowed and trigger the top-center warning pill.
- **Emergency Exit (`Ctrl+C`) & Watchdog**: Pressing physical `Ctrl+C` removes hooks immediately, hides all overlays, and emits `{"event": "aborted"}` over stdout so `pc_control_mcp.py` aborts any in-flight `run_gui_sequence`. A `25s` deadline watchdog guarantees the PC never stays locked if the parent process stops or crashes.
